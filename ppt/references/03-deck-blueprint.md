# 03 · deck 蓝图：六章 × 页数配比

本文件解决一件事：**从"核心功能清单"变成一份有页码、有标题、有形态的页面蓝图。**

产出的 `blueprint.md` 是第 4 步拼 deck 的唯一依据。

## 二、章节顺序的三条规则

### 规则 1：先"是什么"，再"怎么走"，再"怎么搭"，最后"具体怎么做"

顺序固定为 **定位 → 流程 → 功能架构 → 技术架构 → 核心功能 → 边界**。

理由：观众是"先建立全局、再往里钻"的认知路径。把核心功能页放前面，观众不知道它在系统里的位置；放最后又太晚——所以**功能架构之后、结语之前**是核心功能页的正确位置。

### 规则 2：核心功能页必须有一页"索引"

第 9 页（功能地图 + 本次重点）不是可选项。8–15 个核心功能如果直接一页页讲下去，观众记不住讲到哪了。索引页让观众随时知道"我在第 3 个功能，后面还有 5 个"。

### 规则 3：六章标题写成"读者问题"

不要用「第二章 业务流程」，用**读者脑子里的问题**：

| 章节 | 章节标题写法 |
|---|---|
| 一 | 「这是一个什么系统」 |
| 二 | 「一笔业务怎么走完」 |
| 三 | 「系统有哪些能力」 |
| 四 | 「它是怎么搭起来的」 |
| 五 | 「核心能力逐个看」 |
| 六 | 「它不做什么」 |

## 三、反单调（咨询风格最容易翻车的地方）

连续几页骨架一样，deck 立刻变得像 Word 文档。硬约束：

| 约束 | 值 |
|---|---|
| 相邻两页骨架必须不同 | 是（截图页 ↔ 架构图页 ↔ 图形页 交替） |
| **截图页连续上限** | **4 页**。第 5 页前必须插一页架构图 / 流程图 / 数据页 |
| 等宽卡片网格全篇 | ≤ 2 次 |
| 文本分类页全篇占比 | ≤ 1/3，且**连续不超过 2 页** |
| 数据页连排 | 15 页 deck 里 6–9 页为宜 |

**核心功能章节的排法**：8 个核心功能不要 8 页连着排。做法是在第 4 个之后插一页"四个功能的共同机制"（架构图或序列图），再继续后 4 个。这一页还能顺带把跨功能的机制讲清楚，一举两得。

```
✅ 正确：截图 截图 截图 截图 → 机制图 → 截图 截图 截图 截图
❌ 错误：截图 ×8
```

## 四、每页要写清的五个字段

`blueprint.md` 的每一页必须写全这五项，缺一项第 4 步就会卡住：

```markdown
### P13 · 五 · 核心功能点 · 【功能名】
- 标题：【动作式结论 —— 带动词和结论，不是图名】
- 形态：截图页（左 504 + 间距 60 + 右 1316）
- 素材：images/13-【功能名】.png
- 标注：① 【机制要点一】 ② 【机制要点二】 ③ 【机制要点三】
- 源码落点：【模块】/【页面组件】.tsx:【起始行】-【结束行】（对应哪个要点）、
            【服务层】/【服务文件】.py:【起始行】-【结束行】（对应哪个要点）
- 备注（演讲）：这一页重点讲什么、不讲什么
```

**「源码落点」是硬要求**。写不出落点的页，说明这一页的内容没有依据，要么补勘察，要么删页。
上例里的 `【...】` 占位符**必须全部替换**为本次勘察的真实结果 —— 一个都不许沿用示例。

**「备注」也要写**：deck 是给人讲的，不是给人读的。备注就是讲这页时说的话（见第 6 步 deck 骨架的 `data-notes` 属性）。

## 五、标题的写法（本技能最容易做砸的一项）

标题必须写**动作式结论**，不是图名。

| ❌ 图名式 | ✅ 动作式结论 |
|---|---|
| 录入页 | 一次录入要过三道关 |
| 流程总览图 | 可处理量不能超过剩余可用量 |
| 技术架构图 | 三个依赖撑起一个前后端分离架构 |
| 能力介绍 | 一句提问，三步到结果 |
| 系统功能架构 | 四个业务域覆盖主链路全程 |
| 数据模型 | 状态不是独立实体，挂在主记录上 |

判断方法：**标题里有没有动词和结论**。有 → 合格。只是一个名词短语 → 重写。

## 六、蓝图自检清单

- [ ] 每一页都有：页码、章节、动作式标题、形态、素材来源、源码落点、演讲备注
- [ ] 六章齐全（缺章节要在备注里说明理由）
- [ ] 核心功能页数在 8–15 之间，且每个都有对应界面
- [ ] 有"功能地图 + 本次重点"索引页
- [ ] 截图页连续不超过 4 页（已插入机制图）
- [ ] 相邻两页骨架不同
- [ ] 封面 / 目录 / 落版 / 合规声明页齐全
- [ ] 总页数在用户选定的档位内
- [ ] 每个技术结论都有源码落点
- [ ] 没有一页是纯文字堆砌（最差也要是文本分类页的「线 + 框」骨架）
