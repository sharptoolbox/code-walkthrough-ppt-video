# 07 · 已知坑清单

按「症状 → 根因 → 修法」组织。**动手前先扫一遍**，能省掉大部分返工。

## A. 截图（最容易白忙一阵的一环）

### A1 截图尺寸不对（1600×900 变成 1080×617 之类）

**症状**：`--window-size=1600,900` 但输出尺寸小一圈。

**根因**：Windows 显示缩放（本机 150%）会等比缩小视口。

**修法**：无头浏览器必须加 **`--force-device-scale-factor=1`**。`shoot_page.py` 里已有，不要删。

### A2 ★ 截图正好 1600×900，但**底部内容被切掉**（分页器 / 底部按钮消失）

**症状**：图片尺寸完全正确，可是页面最底下那条不见了，或者下方多出一条空白带。

**根因**：`--window-size` 设的是**窗口尺寸，不是视口尺寸**。窗口标题栏 + 边框会吃掉约 **16×95px**，真实视口只有 1584×805。页面按 900px 高布局，最后 95px 就永远拍不到。

**排查手法**：在页面里塞一段诊断脚本，无头跑 `--dump-dom` 打印 `window.innerWidth / innerHeight`：

```bash
chrome --headless=new --window-size=1600,900 --dump-dom <带诊断脚本的页面>
```

看到 `iw:1584, ih:805` 就是这个问题。

**修法**：`shoot_page.py` 已处理——**窗口开大一圈再裁**：

```python
"--window-size=%d,%d" % (w + 40, h + 120),   # 开大，保证视口 ≥ 目标
im = Image.open(png)
if im.size != (w, h) and im.width >= w and im.height >= h:
    im.crop((0, 0, w, h)).save(png, "PNG", optimize=True)
```

**发现"尺寸对但内容缺"，先怀疑这条，不要先去改 CSS 布局**（会白改）。

### A3 改了 HTML，重新截图还是旧版

**根因**：Chrome 用户数据目录留了缓存。

**修法**：`shoot_page.py` 已加两条——渲染每页前 `shutil.rmtree(profile, ignore_errors=True)` 清 profile，启动参数带 `--incognito`。**不要图省事复用同一个 profile 连续拍多页。**

### A4 ★ DPR 2 出图后，裁剪坐标算错只留了左上角

**症状**：期望 1600×900，实际得到一张 1600×900 的"放大局部"，或裁出 800×450。

**根因**：`--force-device-scale-factor=2` 时，截图实际是 **3200×1800** 物理像素。若按 1600×900 去 `crop`，会只保留左上四分之一。

**修法**：裁剪要用**物理像素**尺寸；或者干脆**按 DPR 2 出图后用 Pillow 缩到 3200×1800 的目标尺寸**（本技能要的就是 3200×1800，不需要缩）。`shoot_page.py` 里 `w/h` 与 `dpr` 是分开算的，改参时注意。

### A5 拼版图看着糊 / 缩略图不清晰

**根因**：拼版是把 3200×1800 的图缩到网格格子，缩得太狠。

**修法**：拼版只用于"一眼过完"，判断细节要看原图。拼版单格宽度建议 ≥ 640px（脚本默认按 4 列排）。

### A6 ★ 截图「静悄悄」失败：Chrome 报 0x3，白等一整个 timeout

**症状**：每张图都要等满 timeout 才失败，Chrome 打日志：

```
Failed to write file <输出目录>\<页面>.png.raw.png: 系统找不到指定的路径。 (0x3)
```

**根因**：`--screenshot` 收到的是**相对路径**。Chrome 的工作目录**不等于**调用方的当前目录，相对路径解析不到。单页实测白等 71.7 秒。

**修法**：传给 `--screenshot` 的路径一律 `os.path.abspath()`。`scripts/shoot_page.py` 已修，自建脚本时注意：

```python
raw = os.path.abspath(out_png) + ".raw.png"
```

## B. 界面重绘

### B1 中文文字溢出容器

**症状**：按钮文字被截断、表格列内容换行撑高、标签压到相邻元素。

**根因**：中文比英文宽（中文 ≈ 字号 × 1.0，英文 ≈ 字号 × 0.55），估算时按英文算就会爆。

**修法**：改文案时按 `字数 × 字号` 估算宽度；表格固定宽度列留 5% 余量；拿不准就在浏览器里看。

### B2 表格区高度不稳定，分页器被挤出画面

**根因**：用 flex 或 `margin-top:auto` 让表体弹性，在不同内容量下表现不稳定。

**修法**：用**绝对定位三段法**（工具栏 / 表体 / 分页器），高度完全确定。见 `02-ui-redraw-light.md` 第四节，四套骨架都已按此写。

### B3 浅色界面重绘后"看起来不像原系统"

**症状**：用户反馈"这不是我们的界面"。

**根因**：把原系统的渐变 / 阴影 / 圆角特征都拉平了（Flat Design 要求）。

**评估**：这是**有意为之的代价**。判断标准是——**结构、导航层级、表头文案、按钮文案**是否 1:1 还原。这几项对了，用系统的人就认得出。

**缓解**：
- 保留布局特征（深色顶栏、侧栏宽度、多标签页、面板分区）
- 保留原系统的品牌主色
- deck 里明确写「界面为按源码结构重绘的示意页面」
- 如果用户手上有真实截图，**优先用真实的**（真图永远比重绘有说服力）

### B4 界面里的红和 deck 的红打架

**症状**：一页里出现两种红，观众分不清"这是系统状态"还是"这是你要我看的地方"。

**根因**：系统状态色（危险红 `#C4320A`）与 deck 标注红（`#CC0000`）都是红。

**修法**：见 `04-layouts.md` 第五节「红色唯一性在截图页的重新解释」。三条：
1. 界面状态红用低饱和 `#C4320A`（偏橙）
2. deck 标注红 `#CC0000` 集中给标注
3. **同一页里界面红与标注红不能紧邻**

### B5 ★ 宽表格被内容撑开，右侧列被裁掉

**症状**：列数较多的列表页（10 列以上）截图时，最后一两列被切在画面外；或者表格压出卡片右边缘。`rects.py` 会显示表头 `w` 远大于其容器（例如 `w=1438` 而容器只有 `958`）。

**根因**：`.tbl` 只写了 `width:100%`，没有 `table-layout:fixed`。表格默认是 auto 布局 —— 单元格内容的固有最小宽度加起来超过容器时，表格会**撑破容器**，`overflow:hidden` 再把溢出部分硬裁掉。（百分比列宽在这种情况下一律失效。）

**修法**：骨架里的表格加 `table-layout:fixed`，并给单元格加省略号：

```css
.tbl{width:100%;table-layout:fixed;border-collapse:collapse;font-size:16px}
.tbl th{...;white-space:nowrap;overflow:hidden;text-overflow:ellipsis}
.tbl td{...;white-space:nowrap;overflow:hidden;text-overflow:ellipsis}
```

注意：加了 `fixed` 后列宽严格按 `<th>` 上的百分比分配，**窄列要留得下中文字**（`5.6% × 952 ≈ 53px`，减去左右 padding 后只够两个字，列再窄就要缩 padding 或减列）。

**自检**：截图后跑 `rects.py`，确认 `thead` 的 `槽 w` ≈ 其父 `panel` 的 `槽 w − 左右内边距`。

## C. deck 组装

### C1 图片裂了

**症状**：deck 打开后截图位置是空白 + 裂图图标。

**根因**：① 只发了 html 没带 `images/`；② html 与 `images/` 的相对位置变了；③ 用了绝对路径 `file:///D:/...`。

**修法**：
- 交付必须**整目录**一起给
- 一律用**相对路径** `images/xxx.png`
- 超过 6 张截图**不要** base64 内联（文件会膨胀到几十 MB，浏览器翻页卡）

### C2 缩放后左偏黑边

**根因**：用了 `flex 居中 + transform: scale(center)`——1920px 元素在窄视口下溢出。

**修法**：用 `04-layouts.md` 第一节的 `fit()` 方案（`transform-origin: top left` + 手动算 `translate`）。

### C3 ★ 标注框对不准 / 圆标压住标题

**症状**：框整体偏上偏左；或框位置对了，但编号圆标压住了卡片标题的第一个字。

**根因（两个，常同时出现）**：

1. 截图比例不是 16:9，`object-fit:cover` 把图裁了，而标注坐标是按整图比例算的。
2. **拿渲染图目测估坐标。** 缩略图和大图的比例会骗人，目测误差常在 20–40px —— 足以让圆标正好压在标题上。这是本坑最主要的来源。

**修法**：

- 截图必须先归一化到 1600×900。**不要直接把不同比例的图丢进 `images/`。** 换了截图比例就要同步改槽比例。
- **不要目测。** 用 `scripts/rects.py` 在无头浏览器里读元素的真实 rect，直接拿「槽 x/y/w/h」当框坐标：

  ```bash
  python "<skill>/scripts/rects.py" --in "<工程>/ui" > "<工程>/_build/rects.txt"
  ```

- 圆标按 `references/04-layouts.md` 的定位表放：`cx = box.x − 24`、`cy = box.y + 26`。
- 注意：**卡片之间的间隙只有 8–10px，塞不下直径 34px 的圆标。** 所以圆标不能骑在框的上下边线上，只能放在框左边线外侧的页面底色带上。

### C4 标注框越界（跑到截图外面）

**根因**：手写坐标时估错，或 `x+w` 超 1；或框贴着左边界导致圆标 `cx < 16`。

**修法**：`check_deck.py` 会报越界。约束：

- 框：`x+w ≤ 1316`、`y+h ≤ 740`
- 圆标：`16 ≤ cx ≤ 1300`、`16 ≤ cy ≤ 724`
- 框左端 `box.x ≥ 44`（否则 `box.x − 24 < 16` 越界）

### C8 ★ 左栏边界条与页脚重叠

**症状**：截图页左下角的「④ 边界」提示（`.bound`）与页脚小字（`.pfoot`）叠在一起，两行字互相压住，看起来像排版事故。

**根因**：`.bound` 原先用 `bottom:0` 贴左栏底部（y≈1060），而 `.pfoot` 是整页页脚 `bottom:20px`（y≈1046–1060）—— 两者落在同一段垂直区间里，必重叠。**只有同时用这两个元素的页面才会暴露**，所以容易漏。

**修法**：`.bound` 用 `bottom:36px`（模板已内置），把最下面 36px 让给页脚。若某页确实不需要页脚，删掉 `.pfoot` 即可，但**不要**两样都留着又都不动位置。

> 这一条是打包前做 preview 配图时目检发现的 —— 说明「截完图一定要看整页渲染」，只看缩略图会漏掉这种底部重叠。

### C5 ECharts 在打印 PDF 里全空白

**根因**：canvas 在页面未激活时不渲染。

**修法**：deck 加 `?all` 参数（一次渲染全部页面）；或用 `assets/templates/echarts.min.js` 离线版 + 同步初始化。

### C6 treemap 层级颜色报错

**根因**：模板库 B 的 treemap `levels` 内混写了颜色。

**修法**：`levels` 里只用 `colorSaturation` / `itemStyle` 之一，不混写。

### C7 模板 SVG 复制后整体偏上 / 偏下

**根因**：模板自带「图底说明」行占了 viewBox 空间。

**修法**：删掉说明行，并把 viewBox 收至内容下沿。

## D. 内容与质量

### D1 ★ 凭空写"高可用 / 微服务 / 缓存层"

**症状**：deck 里出现了源码中根本没有的技术特征。

**根因**：AI 顺手补全"看起来专业"的架构词。

**修法**：见 `05-diagrams.md` 第三节的**禁忌词表**。每个词都要有证据：

| 写了 | 必须有 |
|---|---|
| 微服务 | 多个独立部署单元 |
| 高可用/集群 | nginx.conf / k8s 副本数 / 注册中心配置 |
| 消息队列 | MQ 依赖 + 生产者/消费者代码 |
| 缓存层 | Redis / Memcached 依赖与配置 |
| 数据权限/多租户 | 租户字段 + 查询里强制注入的代码 |
| CI/CD | `.gitlab-ci.yml` / `Jenkinsfile` / `.github/workflows` |

**勘察阶段就要专门记一份「源码里没有的东西」清单** —— 那份清单是「能力边界」页的素材，也是整份 deck 可信度的来源。

### D2 标题写成了图名

**症状**：页面标题是「订单录入页」「技术架构图」这种名词短语。

**根因**：把页面当成"展示图"，没当成"传达结论"。

**修法**：标题必须是**动作式结论**。判断方法：标题里有没有动词和结论。见 `03-deck-blueprint.md` 第五节。

### D3 把密钥 / 真实数据带进 deck

**症状**：deck 里出现源码中的 API Key、secret_key、真实客户名、内网 IP。

**根因**：勘察时看到了就顺手用上。

**修法**：
- 重绘界面数据**全部仿真**
- 源码里的密钥 / 内网地址**一律不得出现在 deck 任何位置**（含页脚、`alt` 文本、**HTML 注释**、CSS 注释）
- `check_deck.py` 第 10 项会扫 `api_key`、`secret`、`password=`、内网 IP 段
- 收尾页要有「界面为按源码结构重绘的示意页面」+ 数据仿真声明

> **勘察时如果发现源码里有明文密钥，重点标注出来，deck 全程规避**——这条值得单独提醒用户（源码本身的安全问题）。

### D4 核心功能挑到了没有界面的

**症状**：某页核心功能写不出截图，只好用示意图糊过去。

**根因**：违反了"每个核心功能必须能落到一个界面"的硬约束。

**修法**：把它移到「技术架构」章节用架构图/序列图讲，换一个有界面的功能进核心功能页。

### D5 截图页连排太多，deck 变得像说明书

**根因**：8 个核心功能一页页连着排。

**修法**：截图页连续上限 **4 页**；第 5 页前插一页机制图（跨功能的序列图 / 类图 / 活动图）。见 `03-deck-blueprint.md` 第三节。

### D6 截图里的字号缩到 1316 宽后看不清

**症状**：投影时表格内容糊成一片。

**根因**：重绘时按 1600 画布定了过小的字号（照抄了视频那套，但本技能缩放比更大）。

**修法**：用 `02-ui-redraw-light.md` 第四节的**字号规范**：表格正文 ≥16px、表头/按钮 ≥18px。**字号不够用的解法是减内容**（表格只放 6–8 行、查询条件只放 4 个），不是继续缩小。

## E. 环境与工程

### E1 中文路径与脚本文件

Windows 下避免写含中文的**可执行脚本文件**（`.ps1` / `.bat`）——编码会破坏文件名。用 `execute_command` 直接跑命令，或写 UTF-8 的 `.py`。

### E2 删除操作会被拦

受限环境里删除走回收站并 fail-closed。写清理逻辑时用 `ignore_errors=True` 兜底，或干脆"另存新文件、不覆盖旧文件"。

### E3 素材来源要先确认

用户目录里常有几十张同名或近似的截图。**开工前先问清用哪一张**，别猜（对应第 1 步的"顺带要问的"）。

### E4 工程目录与源码目录分离

源码目录**只读引用**，重绘产物写到独立的工程目录。不要往源码目录里写 `ui/`、`images/`——污染用户仓库。
