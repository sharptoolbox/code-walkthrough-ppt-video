本文件是**唯一的版式权威**。所有页面必须严格套用，不得违反。

## 一、画布与页面骨架（硬性规范）

```
画布：1920 × 1080        背景：#FFFFFF（纯白，不允许底色 / 渐变）
页面边距：四边各 20px     安全区：x 20–1900 / y 20–1060
标题区：y 20–170（高 150）
分隔线：y=170，高 5px，纯黑 #000000，横向拉通 x 0–1920（左右顶到画布边缘）
内容区：y 175–1060（1880 × 885）
```

### 分区坐标表

| 分区 | 坐标 | 说明 |
|---|---|---|
| 标题 | x=20, y=20–170 | 48px / 700 / `#333333` / 左对齐 / 区域内垂直居中 |
| kicker（可选） | 右对齐 x=1900，与标题同区 | 18px / 600 / `#A3A3A3` / `letter-spacing:4px` / 大写 |
| 页脚（可选） | y ≤ 1040 | 14px / `#A3A3A3` |
| 分隔线 | y=170，h=5px，x 0→1920 | 纯黑，**必须拉通到画布边缘**，不许只画内容区宽 |
| 内容区 | x 20–1900，y 175–1060 | 1880 × 885 |

### 居中缩放（多页 deck 必须照此实现）

```js
const stage = document.querySelector('.stage');
function fit(){
  const s = Math.min(innerWidth/1920, innerHeight/1080);
  const x = (innerWidth  - 1920*s)/2;
  const y = (innerHeight - 1080*s)/2;
  stage.style.transform = `translate(${x}px,${y}px) scale(${s})`;
}
addEventListener('resize', fit); fit();
```

```css
.stage{width:1920px;height:1080px;transform-origin:top left;position:absolute;top:0;left:0;
       background:#FFFFFF;overflow:hidden}
```

> **不要**用 `flex 居中 + transform: scale(center)`——1920px 元素在窄视口下会溢出导致左偏黑边。

### 对齐与居中规则

- 标题、左栏文字、图形最左元素**一律对齐 x=20**
- 分栏图形在容器内**上下左右居中**
- 通栏图形**左右拉满 + 垂直居中**
- 图标与序号**二选一**（有图标就删 01/02/03）

## 二、五种形态判定（优先级：截图页 ＞ 数据页 ＞ 架构图页 ＞ 图形页 ＞ 文本分类页）

**每一页动手前必须按顺序判断，不得跳步。**

| # | 形态 | 什么时候用 | 从哪儿取 | 容器尺寸 |
|---|---|---|---|---|
| ① | **截图页** | 这一页讲**一个具体功能的界面与机制** | 重绘的浅色界面截图 + SVG 标注层 | 左 504 + 60 + 右 **1316** |
| ② | **数据页** | 内容带**数值序列 / 对比基准 / 占比 / 归因 / 达成率 / 分布** | 模板库 B · 01–28 | 分栏 1120×700 / 通栏 1880×700 |
| ③ | **架构图页** | 讲软件 / IT 系统的构成与运行：分层、应用、数据流、服务拆分、集成、安全、部署、演进或 UML 行为/关系 | 模板库 C · 00–14 | 分栏 1120×700 / 通栏 1880×700 |
| ④ | **图形页** | 有层级/流程/因果/对比/矩阵/时间/闭环/转化/角色×阶段关系，**没有数值**，且**不属于软件 / IT 系统方案** | 模板库 A · 01–22 | 同上 |
| ⑤ | **文本分类页** | 既无结构关系、又无数值，只是「几个并列类目 + 各自说明」 | 模板库 A · 23–27 | 1200 宽绘制，通栏 1.567 |

**判定顺序：**

1. **这一页在讲某个功能的界面和机制吗？** 是 → 截图页。**有界面就必须用截图页**，不许用示意图替代。
2. 有数字要对齐比较吗？有 → 数据页（B·01–28）。用一段文字说「增长 15%」是本页的失职。
3. 没有数字，讲系统的构成 / 运行 / 演进吗？是 → 架构图页（C·01–14）。
4. 也不是，有可画的通用结构关系吗？有 → 图形页（A·01–22）。
5. 都不成立 → 文本分类页（A·23–27），也必须由「线 + 框」构成骨架，**禁止纯段落堆叠、禁止圆点 bullet**。

五种形态可**同页混排**：左讲右图，或通栏大图 + 文字条。

### 坐标表

```
内容区 1880 = 左栏 504 + 间距 60 + 右栏 1316      （右栏占 70%）

左栏：x 20 – 524（宽 504），y 175 – 1060
```

### 左栏结构（自上而下，四段）

| 段 | 元素 | 字号字重色 | 位置（y） |
|---|---|---|---|
| 1 | 功能名（动作式） | 28px / 700 / `#333333` | 起 y=185，行高 1.35 |
| — | 细分隔线 | 1px `#CCCCCC`，宽 504 | 功能名下方 16px |
| 2 | 一句话价值 | 20px / 400 / `#777777`，行高 1.65 | 分隔线下方 16px |
| 3 | ①②③ 机制要点 | 每条 = 编号圆标 + 22px/700 `#333333` 标题 + 20px/400 `#555555` 说明（≤2 行）；条间 20px | 价值句下方 28px 起 |
| 4 | ④ 边界与约束 | 20px / 400 / `#A9720B`（琥珀），左竖线 3px `#E8A33D` | **贴左栏底部** `bottom:0` |

**编号圆标的画法**（左栏内，与右侧标注呼应）：

```
直径 30px 实心圆，填充 = 对应语义色
  ① #CC0000（本页唯一的那处红）
  ②③ #006393

圆标左边缘对齐 x=20，文字左边缘 x=60
```

### 右栏：截图容器

```html
<div class="shot-slot">
  <img src="images/13-【功能名】.png" alt="【功能名】界面示意">
  <svg class="anno" viewBox="0 0 1316 740" preserveAspectRatio="none">
    <!-- 标注层 -->
  </svg>
</div>
```

```css
.shot-slot{position:absolute;left:584px;top:247.5px;width:1316px;height:740px;
  border:1px solid #CCCCCC;border-radius:2px;overflow:hidden;background:#FFFFFF}
.shot-slot img{display:block;width:1316px;height:740px;object-fit:cover}
.shot-slot .anno{position:absolute;inset:0;width:1316px;height:740px;pointer-events:none}
```

**三条硬规则：**

1. **1px 描边，禁阴影**。Flat Design 不允许阴影。白底截图贴在纯白页面上会"飘"，只能靠 `#CCCCCC` 描边建立边界。
2. **`object-fit:cover`**，因为截图是 1600×900（1.778）而槽是 1316×740（1.778）——比例严格一致，不会有裁切。**如果你改了截图比例，必须同步改槽的比例**，否则 `cover` 会裁掉边缘、标注全部错位。
3. **不加顶部总结条**。本形态明确不用顶部总结条，代价是**标题必须承担结论职责**——写成动作式结论。

### 右栏：标注层（SVG 覆盖，不烙进截图）

底图干净可复用；标注是矢量，缩放不糊；同一张底图能在不同页讲不同标注。

| 元素 | 画法 |
|---|---|
| 编号圆标 | r=17，填充 `#CC0000`，白色数字 18px/700 居中 |
| 高亮框 | `stroke:#CC0000; stroke-width:1.5; fill:rgba(204,0,0,.10)`，直角或 rx=2 |
| 引线 | `stroke:#CC0000; stroke-width:0.5; stroke-dasharray:4 4`，长度 ≤ 60px |
| 标注文字（可选） | 13px / `#CC0000`，放在框上方 6px 或圆标右侧 8px |

坐标用**截图本地坐标系（1316 × 740）**。

**圆标放哪才不压字**（实测结论，务必照做）：

截图里「卡片之间的间隙」通常只有 **8–10px**，而圆标直径 34px —— **放不进间隙**。所以不要试图把圆标骑在框的上下边线上。唯一稳定的位置是**卡片左边缘外侧的页面底色带**（宽约 60px）：

| 规则 | 值 | 说明 |
|---|---|---|
| 圆标横向 | `cx = box.x − 24` | 骑在框的左边线、再左移半个直径，落在卡片外底色上，完全不压正文 |
| 圆标纵向 | `cy = box.y + 26` | 贴框顶内侧一点，视觉上归属明确 |
| 框的左端 | `box.x ≥ 44` | 否则 `cx` 会小于 16 越界。贴边的框先内移到 44 |
| 通栏图 / 满宽框 | `box.x + box.w ≤ 1302` | 右侧要留出圆标空间时，先收窄框宽 |

**不要**把圆标放在框内左上角 —— 卡片标题文字通常就在那里，会压住标题。

**约束**：

- 每张截图 **2–4 个标注**，超过 4 个说明该拆页
- 标号 ①②③ 必须与左栏要点**一一对应**，顺序也一致
- 标注**不许压住**关键文字、按钮文案、表头（引线不许穿过表格文字）
- 标注框 `x+w ≤ 1316`、`y+h ≤ 740`，不许越界
- 圆标 `16 ≤ cx ≤ 1300`、`16 ≤ cy ≤ 724`（即 `r−1 ≤ cx/cy ≤ 边 − r + 1`）

> ⚠️ **禁止用目测估坐标。** 缩略图和渲染图的比例会骗人，估算误差常在 20–40px，足以让圆标压住标题、让框落错区块。取坐标的唯一可靠办法是**在无头浏览器里读元素的 `getBoundingClientRect()`** —— 见 `references/06-pipeline.md` 第 2.5 步。

## 四、② 数据页 / ③ 架构图页 / ④ 图形页 / ⑤ 文本分类页

这四种形态的可移植规则已经收录在本文件与 `05-diagrams.md`，不依赖本机的其他技能目录。本节给出当前工作流需要的速查约束。

### 版式选择速判

| 内容形态 | 版式 |
|---|---|
| 有论点 + 有框架 / 评估 / 对标 | **左右分栏**（左文 700 + 间距 60 + 右图 1120×700） |
| 线性推进 / 阶段 / 时间 / 因果链 | **通栏**（图区 1880×700，左右拉满、垂直居中） |
| 单一模型、无文字论据 | 通栏居中放大 |
| 一句核心结论 | 金句聚焦页 |
| 软件 / IT 系统构成、运行或演进 | 架构图页（模板库 C） |
| 并列类目、无结构关系 | 通栏文本分类（A·23–27） |

### 分栏 / 通栏容器坐标

| 版式 | 左栏 | 右栏 | 备注 |
|---|---|---|---|
| 分栏（图） | x 20–720（宽 700） | x 780–1900（1120×700，居中于 y 175–1060） | 图形在 1120×700 内上下左右居中 |
| 分栏（截图） | x 20–524（宽 504） | x 584–1900（1316×740，垂直居中） | **截图页专用** |
| 通栏 | — | x 20–1900（1880×700，垂直居中） | 左右拉满 |

> **两种分栏的左栏宽度不同**（700 vs 504），这是有意的：图形页右栏只需 1120，左栏可以给到 700 放更多文字；截图页右栏要吃 1316，左栏只能给 504。**同一份 deck 里两种分栏可以并存，但同一页只能选一种。**

### 模板库取用要点

- **模板库 A**（`assets/templates/图表模板库.html`）：每个模板是一段独立可复制的内联 SVG。复制后**只替换文字与数值**，不得改坐标骨架 / 配色语义 / 线宽。投放时删掉模板自带的「图底说明」行并把 viewBox 收至内容下沿，否则图形整体偏上。
- **模板库 B**（`assets/templates/echarts图表模板.html`）：每个编号一个函数 `c01()` … `c28()`，照抄 option 后整体替换数据。初始化用 `echarts.init(el, null, {renderer:'canvas', devicePixelRatio:2})`。容器尺寸 = 图表尺寸（右栏 1120×700、通栏 1880×700，高度都是 700，字号不用跟着改）。
- **模板库 C**（`assets/templates/架构图模板.html`）：只用于软件 / IT 系统。先读 **00 图元与连线规范**，再按 `05-diagrams.md` 的映射表选 01–14，复制完整内联 SVG。**分栏按 1120×700、通栏按 1880×700 原尺寸投放，不做缩放折算。**

## 五、配色与字体

| 角色 | 色值 | 占比 | 用在哪 |
|---|---|---|---|
| 主色（红：结论 / 高亮 / **截图标注**） | `#CC0000` | 20% | deck 的高亮与标注 |
| 深蓝（中层 / 机制 / 左栏图标） | `#006393` | 15% | 结构中层、次要要点 |
| 深青（文字主色） | `#333333` | 20% | 标题、正文 |
| 辅助灰（次要文字 / 轴 / 连线） | `#A3A3A3` | 45% | 说明、注释 |
| 浅灰背景 / 描边 / 主场填充 | `#F5F5F5` / `#CCCCCC` / `#FFF2F2` | — | — |
| 边界提示（琥珀） | `#A9720B` / 竖线 `#E8A33D` | — | 截图页第 ④ 条 |

**禁止**：渐变、阴影、发光、3D、高饱和荧光色、彩色 emoji。

### 红色唯一性在截图页的重新解释

咨询规范要求「全页红色只有一处」。但截图页天然有 2–4 个红色标注圆标。**本技能的裁决：**

> **截图页的红色语义只有一个 —— 「这是本页要你看的地方」。**
>
> 因此：标注圆标 / 高亮框 / 引线**全部**用 `#CC0000`（它们属于同一语义），而左栏的 ②③ 编号圆标改用 `#006393`，只有 ① 用 `#CC0000`（它对应最该被看见的那一条）。界面截图里的红是**系统状态色**（低饱和 `#C4320A`），不算 deck 的红，但同一页里界面红与标注红不能紧邻，避免混淆。
