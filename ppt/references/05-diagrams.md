# 05 · 图表取用：六章内容 → 模板编号

本技能不自创图形。**所有架构图 / 流程图 / 数据图都必须从 `assets/templates/` 的三个模板库中选取**。

模板库 C 的编号与判据以本文件和 `../assets/templates/架构图模板.html` 为准，不依赖外部技能。
本文件只解决一件事：**deck 的每一章该用哪个编号。**

## 二、取用口径（三类模板各自的复制规则）

### 模板库 C（架构图）—— 本技能用得最多

```bash
# 打开模板库，先读 00 图元与连线规范
start "" "<skill>\assets\templates\架构图模板.html"
```

- **先读 00 图元与连线规范**，再复制 01–14 对应的完整内联 SVG
- 分栏图按 `1120×700`、通栏图按 `1880×700` **原尺寸投放，不做缩放折算**
- 常规模板只替换组件、层级、分类、状态、消息、注释和图例文字；**坐标骨架、线宽和配色语义不改**
- 类图（13）、序列图（12）、状态图（14）、活动图（11）的**元素数量与关系结构必须随实际内容重建**；分层数 / 分区数 / 列数变化时，按原模板的内边距和间距规则重算坐标
- 连线接在元素边的中点，优先直角走线，交叉不超过 2 处；同层同底色；不画穿层竖向箭头
- 灰底 `#A3A3A3` 标签必须使用 `#333333` 文字；聚合 / 组合菱形在"整体"端，泛化为空心三角
- **红色仅保留一处**，落在最需要被看见的组件或关键交互上

### 模板库 A（示意图形 + 文本分类）

- 每个模板是一段**独立可复制的内联 SVG**。复制后**只替换文字与数值**，不得改坐标骨架 / 配色语义 / 线宽
- 图形页按 1120×700（分栏）或 1880×700（通栏）绘制
- 文本分类图按 **1200 宽绘制**（23–26 高 380；27 含结论带高 404）；通栏等比 **1.567** 投放（1200→1880）
- **投放时删掉模板自带的「图底说明」行并把 viewBox 收至内容下沿**，否则图形整体偏上

### 模板库 B（ECharts 数据图）

```html
<script src="https://cdn.jsdelivr.net/npm/echarts@5.5.1/dist/echarts.min.js"></script>
<script>window.echarts||document.write('<scr'+'ipt src="https://unpkg.com/echarts@5.5.1/dist/echarts.min.js"><\/scr'+'ipt>');</script>
```

离线时把上面的 CDN 换成本技能自带的 `assets/templates/echarts.min.js`（复制到 deck 同级目录并改相对路径）。

- 每个编号一个函数 `c01()` … `c28()`，**照抄 option 后整体替换数据**（数字、分组、系列数、类目名、流向关系、单位）
- 桑基 / 树图 / 箱线 / 气泡 / 力导向等**结构随数据变化的图型必须连关系结构一起重建**
- 初始化：`echarts.init(el, null, {renderer:'canvas', devicePixelRatio:2})`（deck 有居中缩放，dpr=2 才清晰）
- 容器尺寸 = 图表尺寸：分栏 `1120×700`、通栏 `1880×700`
- **已知坑**：treemap `levels` 内不能混写颜色；无头截图 / 打印 PDF 图表全空白 → 把 deck 里 `?all` 参数加上或改同步初始化；value 型 X 轴轴名要设 `nameLocation:'middle'` + `nameGap:34`

## 三、图表页的内容口径

### 从源码出来的图，必须有"证据链"

每张架构图/流程图在 `blueprint.md` 里都要记 `源码落点`。画图时的自检：

- 图上每个组件 / 服务 / 表，能不能指到代码里的一个文件或一个依赖？
- 图上的箭头（调用 / 数据流），能不能指到一段真实的调用代码？
- 图上的分层边界，是从目录结构 / 包结构推出来的，还是自己想的？

**答不上来的元素，从图上删掉。** 一张少两个组件但全都有出处的图，比一张完整但有两处编造的图有价值得多。

### 特别提醒：不许凭空写这些词

以下词汇在源码里没有证据时**一律不得出现**（这是 AI 最容易顺手写上的）：

| 禁忌词 | 需要什么证据才能写 |
|---|---|
| 微服务 / 服务化 | 有多个独立部署单元（多 `Dockerfile` / 多启动类 / 注册中心） |
| 高可用 / 集群 / 负载均衡 | 有 `nginx.conf` / k8s 副本数 / 注册中心配置 |
| 消息队列 / 异步解耦 | 依赖里有 MQ 客户端 + 有生产者/消费者代码 |
| 缓存层 | 依赖与配置里有 Redis / Memcached |
| 分库分表 | 有分片配置或分片键逻辑 |
| 数据权限 / 多租户 | 有租户字段 + 查询里强制注入租户条件的代码 |
| CI/CD | 有 `.gitlab-ci.yml` / `Jenkinsfile` / `.github/workflows` |

**勘察时发现源码里"没有"的东西，要专门记一份清单** —— 那份清单反而是「能力边界」页最好的素材，也是这份 deck 可信度的来源。
