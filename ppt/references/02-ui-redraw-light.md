# 02 · 浅色界面重绘：从源码还原可截图的仿真页面

这套流水线**不要求系统能跑起来**。老系统依赖内网、许可证过期、前端构建链断掉都很常见；但界面是项目介绍里最有说服力的载体。

做法：**从前端源码里读出页面的结构与文案，用纯 HTML 重新画一个静态页面，再高分辨率截图。**

> ### 合规前提（必须遵守）
> 1. 重绘页面里**不得出现真实客户数据、真实账号、密钥、内网地址**。一律用仿真数据。
> 2. deck 里提到界面时用「界面示意」而非「系统实际截图」的措辞。收尾页要有声明。
> 3. 原系统的 Logo、商标，除非用户明确授权，否则用中性文字标题替代。
> 4. **源码里如果有明文密钥 / 密码 / API Key，deck 全程不得出现**（含页脚、HTML 注释、alt 文本）。

## 一、为什么是浅色（与视频技能的关键差异）

`code-walkthrough-video` 的规范要求：原系统是浅色时**重绘成深色**。那是为深色视频服务的。

**本技能的规则相反：一律重绘成浅色。**

| 理由 | 说明 |
|---|---|
| 与 deck 融合 | 咨询 deck 是**纯白 Flat Design**。深色截图贴上去就是一块黑斑，破坏整页节奏 |
| 信息可读 | 截图右栏占 70%，会被缩到 1316 宽。浅色界面在缩小时对比度衰减更慢，表格线、字段名更清楚 |
| 保真 | 多数中后台系统本来就是浅色。浅色重绘更接近原系统，观众一眼认得 |

**代价**：截图和纯白页面之间"边界不清"。解决办法是给截图容器加 **1px `#CCCCCC` 描边**（不是阴影——Flat Design 禁用阴影），见 `04-layouts.md`。

## 二、从源码里读什么（"还原清单"）

按顺序扫，每一步都往同一张清单里填。**只读与"长什么样"有关的部分，不要读业务逻辑。**

| 要还原的东西 | 在哪读 | 读法 |
|---|---|---|
| 页面标题 / 导航结构 | 路由表、菜单配置、页面注册表 | 路由的 `meta.title`、菜单 `name`、`pageId → title`；层级就是导航层级 |
| 整体外壳 | 主布局组件（`App.tsx` / `MainLayout.vue`） | 有没有顶栏 / 侧栏 / 多标签页 / 右侧面板 / 底部面板？各自宽度与高度 |
| 区块划分 | 页面组件模板 | 找出「查询条件区 / 操作工具栏 / 表格 / 分页 / 抽屉 / 弹窗 / 明细区」这几块 |
| 表格列 | `columns` 定义、`<el-table-column>`、`<th>` | 列的 `label` 即表头文案，顺序即列顺序；`width` 决定宽度比例 |
| 表单项 | 表单 schema、校验规则、`<label>` | `label` 是字段名；`required` 加红星；`type` 决定控件（输入框/下拉/日期/开关） |
| 状态标签 | 枚举 / 字典常量 | 枚举值的中文名 + 颜色语义（成功/警告/危险/中性） |
| 主色与字体 | **CSS 变量**（`:root` 里的 `--primary` 等） | 拿到主色与背景色，其余自己配。**这是浅色重绘最重要的输入** |
| 按钮与操作 | 表格行操作列、工具栏按钮 | 按钮文案通常就是"下一页要讲的功能" |
| 示例数据 | mock 文件、`__mocks__`、种子数据、注释里的示例 | **只借用字段结构与取值风格**，值自己编 |
| 图标 | 图标库名称（lucide / element-plus / antd） | 用**单色线稿符号**替代，不要复制品牌图标 |

### 一个常见误区

不要试图"把源码跑起来看真实页面"。前端源码经过打包、主题注入、权限过滤之后，直接读反而更准；而且真实环境经常起不来。**读源码 = 更可控的还原。**

## 三、还原到什么程度

**结构 1:1、文案 1:1、数据仿真。** 判断标准很简单：

> 一个用过这个系统的人，看一眼就认得出"这是那个页面"；但仔细看数据，发现不是真实数据。

| 要像 | 可以不像 |
|---|---|
| 外壳布局（侧栏宽度、标签页、面板分区） | 精确的像素间距 |
| 导航层级与菜单文案 | 菜单图标的具体形状（统一符号即可） |
| 页面标题、表头、按钮文案 | 真实的主题皮肤细节（圆角、阴影） |
| 字段顺序与分组 | 复杂交互动效 |
| 状态标签的文字与色彩语义 | 数据的真实取值 |

## 四、构图规范（不遵守就会在 deck 里出问题）

| 项 | 值 | 原因 |
|---|---|---|
| 画布 | **1600 × 900**（16:9） | 与 deck 右栏容器同比例，等比缩到 1316 宽不变形 |
| 设备像素比 | **DPR 2**（出图 3200×1800） | 缩到 1316 显示时等效 DPR 2.43，怎么放大都清晰 |
| 缩放 | 100%，**无滚动条** | 有滚动条会拍进画面，还会让内容高度算不准 |
| **安全边距** | 左 / 右 ≥ 28px，上 / 下 ≥ 20px 不放**关键**内容 | 标注圆标会压在边缘区域，给它们留位置 |
| 主字号 | 见下方「字号规范」 | 缩到 1316 宽后仍要能读 |
| 侧边导航宽度 | 200 ~ 260px | 太窄画不下中文菜单，太宽挤压内容区 |
| 顶栏高度 | 52 ~ 64px | |
| 表格行高 | 40 ~ 48px | 一屏能放 8 ~ 12 行，信息密度刚好 |
| 配色 | **浅色系统色**，见第五节 | |

### 字号规范 —— 这条是本技能特有的，别照抄视频那套

视频里截图卡片是 1400 宽，本技能缩到 **1316** 宽（缩放比 0.8225）。所以字号要按"缩完还能读"来定：

| 元素 | 1600 画布下的字号 | 缩到 1316 后的等效字号 |
|---|---|---|
| 页面主标题 | 22 ~ 24px | 18 ~ 20px |
| 区块标题 | 20 ~ 22px | 16.5 ~ 18px |
| 表头 / 按钮 / 状态标签 | **18 ~ 20px** | **14.8 ~ 16.4px** |
| 表格正文 / 表单项 | **16 ~ 17px** | **13.2 ~ 14px** |
| 导航菜单 | 18 ~ 19px | 14.8 ~ 15.6px |
| 辅助说明 / 页脚 | 14 ~ 15px | 11.5 ~ 12.3px |

**底线**：表格正文不小于 16px，表头与按钮不小于 18px。低于这个数，缩到 1316 宽后在投影仪上就糊了。

> 字号不够用的解法不是继续缩小，而是**减内容**：表格只放 6~8 行、查询条件只放 4 个、表单只放关键字段。截图不是功能说明书，把要点露出来就够。

### 表格区用绝对定位切三段（版式稳定的关键）

中后台页面最容易翻车的地方是"表格区高度不确定"，导致**分页器被挤出画面**或底部挂一条空白带。用 flex 或 `margin-top:auto` 试着挤，在不同内容量下表现不稳定。

**可靠做法**：把表格容器切成三个**绝对定位**的区块，高度完全确定，谁都挤不动谁。

```css
.tablewrap{flex:1;min-height:0;position:relative;background:#fff;
  border:1px solid var(--line);border-radius:6px;overflow:hidden}
.tbar  {position:absolute;left:0;right:0;top:0;    height:52px; ...}   /* 工具栏 */
.tbody {position:absolute;left:0;right:0;top:52px; bottom:54px;overflow:hidden} /* 表体，弹性 */
.pager {position:absolute;left:0;right:0;bottom:0; height:54px; ...}   /* 分页器 */
```

四套骨架里都是这么写的，**照抄这套结构**，后面改内容不会把版式改崩。

## 五、浅色配色规范

### 跟原系统走，但把主色"收"到咨询配色的邻居

优先级：**原系统 CSS 变量 > 本规范默认值**。

```css
:root{
  /* 外壳 */
  --bg-app:      #EEF2F6;   /* 页面底 */
  --bg-panel:    #FFFFFF;   /* 卡片 / 表格底 */
  --bg-muted:    #F5F7FA;   /* 次级区块 / 表头底 */
  --bg-subtle:   #E9EEF7;   /* hover / 选中行 */
  --border:      #D5DCE6;   /* 描边 */
  --border-soft: #E6EBF2;   /* 表格分隔线 */

  /* 文字 */
  --text-main:   #0F172A;   /* 主文字（近黑，不用纯黑） */
  --text-2:      #475467;   /* 次要文字 */
  --text-3:      #667085;   /* 辅助文字 / 表头 */

  /* 主色（原系统的品牌蓝，一般落在这个区间） */
  --primary:     #155EEF;
  --primary-soft:rgba(21,94,239,.10);

  /* 状态色（低饱和，避免与 deck 的红打架） */
  --ok:          #157F3D;  --ok-soft:      #ECFDF3;
  --warn:        #C97A10;  --warn-soft:    #FFF7E6;
  --danger:      #C4320A;  --danger-soft:  #FEF3F2;
}
```

### 三条硬规则

1. **主色只用在三处**：主按钮、选中态（导航/标签页/选中行）、关键数值。不要到处刷蓝。
2. **界面的红 ≠ deck 的红**。界面状态红用 `#C4320A`（偏橙，低饱和），deck 标注红用 `#CC0000`。两者要在同一页里能分清——否则观众分不清"这是系统状态"还是"这是你要我看的地方"。
3. **禁用**：渐变背景、投影、发光、3D。原系统有渐变的地方**拉平**（`linear-gradient` → 单色）。理由：deck 是 Flat Design，界面里带渐变会显得不是同一套东西。装饰性的深色顶栏（如 `#0F172A`）可以保留——那是布局的一部分，不是装饰。

### 外壳元素的处理

| 原系统有 | 怎么画 |
|---|---|
| 深色顶栏（`#0F172A` 之类） | **保留**，这是布局特征，也是截图里唯一合理的深色块。文字用白 |
| 侧边导航 | 白底 + 深色文字 + 选中项主色左竖条 |
| 多标签页 | 保留，选中标签白底 + 主色下划线 |
| 右侧 AI 面板 | 保留，浅灰底 `#FAFBFC` + 白底气泡 |
| 底部面板（日志/事件） | 保留，白底 + 分隔线 |
| 可拖拽分隔条 | 简化成 1px 竖线，可加一个小把手点 |
| 登录页 | 一般**不作为核心功能页**；需要时并入「整体介绍」 |

## 六、动手：四套骨架

`assets/ui-shell/` 里给了四套可直接改的骨架：

| 文件 | 用途 | 典型场景 |
|---|---|---|
| `shell-shell-light.html` | **三栏工作台外壳**：深色顶栏 + 侧栏 + 多标签主区 + 右侧 AI 面板 + 底部日志面板 | 讲"系统整体长什么样"、讲 AI 面板、讲操作日志 |
| `shell-list-light.html` | **列表页**：筛选区 + 工具栏 + 表格 + 分页 | 讲查询、台账、待办列表 |
| `shell-form-light.html` | **表单页**：分区表单 + 明细表格 + 底部操作条 | 讲录入、编辑、提单 |
| `shell-detail-light.html` | **详情页**：主信息 + 从表明细（多个子表格） | 讲详情、主从关系 |

用法：复制一份到工程目录的 `ui/` 下改名，然后按"还原清单"改文案、改列、改状态标签。

**一张截图 = 一个 html 文件**，文件名就是截图名（`03-order-search.html` → `03-order-search.png`）。

> 三栏工作台外壳最复杂也最值钱——**多数项目的"整体介绍"页和"AI 能力"页都靠它**。先改它，其他三套都是从它派生出来的。

### 修改时的手工核对

改完 HTML 之后，**先在浏览器里打开看一眼**（尺寸设 1600×900 的窗口，或直接无头截图看结果）。重点检查：

- 文字有没有溢出容器（中文比英文宽，容易挤爆）
- 表格列加起来会不会超宽（给固定宽度列分配时留 5% 余量）
- 状态标签的颜色语义对不对（成功=绿、警告=橙、危险=红、中性=灰）
- 顶栏/侧栏的品牌名有没有被边缘裁掉

## 七、截图

```bash
python "<skill>/scripts/shoot_page.py" --in "<工程>/ui" --out "<工程>/images"
```

脚本做的事：找 Chrome/Edge → 无头打开每个 html → 截成 **1600×900、DPR 2** 的 PNG → 生成 `contact_sheet.png` 拼版。

### 四个必知的坑（脚本里都已处理，自己写截图命令时要注意）

1. **Windows 显示缩放**会让 `--window-size` 失效（150% 缩放下 1600×900 只截出 1080×617）。必须加 `--force-device-scale-factor=1`。
2. **`--window-size` 是窗口尺寸，不是视口尺寸**。窗口标题栏和边框会吃掉约 **16×95px**，真实视口只有 1584×805——页面最底下那条（分页器、底部按钮）永远拍不到，而图片尺寸看起来完全正常。脚本的做法是**窗口开大一圈再裁**：`--window-size=w+40,h+120`，截图后 `crop(0, 0, w, h)`。
3. **Chrome 用户数据目录有缓存**。改了 HTML 重新截图可能拿到旧版。脚本每页渲染前清 profile + 带 `--incognito`。
4. **DPR 2 的图在 Python 里是 3200×1800**。裁剪前先确认实际像素尺寸，别按 1600×900 去 crop（会只留左上角四分之一）。

> 如果输出尺寸不对，或者尺寸对但**底部内容缺了一块**，先查这四项，**不要先去改 CSS 布局**（会白改）。

### 拼版

脚本产出的 `contact_sheet.png` 把所有截图排成一张。**每次出完截图先看拼版**，一屏看完所有画面，比逐张点开快得多。重点看：

- 有没有整页发虚（字号太小）
- 有没有页面之间风格不统一（配色/字号/圆角不一致）
- 有没有内容溢出或右侧留白过多

## 八、下一步：标定标注点

截图有了之后，要在 deck 页里给每张截图标 `annos`（讲解时圈出来的区域）。坐标用**截图本地坐标系 1316 × 740 的像素值**（与 `04-layouts.md` 一致，不换算比例）：

```json
{"n": "1", "box": [44, 310, 396, 66], "circle": [20, 336]}
```

`box` = `[x, y, w, h]`（框左上角 + 宽高），`circle` = `[cx, cy]`（编号圆标圆心）。

取坐标的唯一可靠办法是**读元素真实 rect，不许目测**：

```bash
python "<skill>/scripts/rects.py" --in "<工程>/ui" > "<工程>/_build/rects.txt"
```

`rects.py` 输出的 `槽 x/y/w/h` 已经换算到这个坐标系，直接抄。越界由 `check_deck.py` 兜底：`box.x + box.w ≤ 1316`、`box.y + box.h ≤ 740`。

### 标注的画法与数量约束

见 `assets/annotation.md`。要点：

- **每张截图 2–4 个标注**，不是越多越好。超过 4 个说明这页想讲的事太多，拆页
- 编号 ①②③ 必须与左栏要点**一一对应**
- 标注圆标用 `#CC0000` 实心 + 白色数字；高亮框用 `#CC0000` 1.5px 实线 + 半透明填充 `rgba(204,0,0,.10)`
- 引线用 `#CC0000` 0.5px 虚线，长度 ≤ 60px，**不许穿过表格文字**
