# 04 · 自绘图表与分镜

## 一、为什么必须有自绘图表

截图只能说明"界面长这样"。架构、数据流、状态流转、设计取舍这些东西，**界面里看不见**，只能画出来。一支讲得清楚的视频，图表和截图的比例大约是 **4:6 到 6:4**，交替出现。

规则：

- **讲结构** → 图表
- **讲落地** → 截图
- 每章至少一张图；连续两张截图之间最好插一张图，否则画面节奏发闷

---

## 二、图表类型库

按讲解目的选，不要按"好看"选。

| 类型 | 什么时候用 | 画法要点 |
|---|---|---|
| **分层架构** | 片头后第一张，交代系统由哪几层组成 | 左侧竖排分层条，右侧列该层的模块；自下而上或自上而下都行 |
| **模块地图** | 系统有 5~12 个并列模块时 | 网格排布，每个模块一个卡片；用颜色分组 |
| **主流程** | 讲一条链路从头走到尾 | 横向步骤卡 + 箭头；步骤 ≤ 6 个 |
| **分支流程** | 流程里有判断（成功/失败、审批通过/驳回） | 主干横排，分支向下引出 |
| **数据流** | 讲数据从哪来到哪去、经过哪些加工 | 左到右，方框=存储，圆角=加工 |
| **状态机** | 讲对象的状态怎么流转 | 状态圆 + 有向边，边上标触发条件 |
| **时序/调用链** | 讲多个角色怎么交互 | 竖线泳道 + 横箭头；角色 ≤ 5 个 |
| **对比** | 讲"以前怎样、现在怎样"或"为什么选 A 不选 B" | 左右两栏，逐条对齐 |
| **链路回顾** | 收尾，把全片串一遍 | 一横排小卡片 + 箭头，一眼看完全程 |

## 三、图元 API（`project/src/diagrams.tsx`）

所有图都画在 **1600 × 826** 的画布里，`viewBox="0 0 1600 826"`，**坐标即像素**。

```tsx
import { DTitle, Arrow, NodeBox, ChipS, chipW, Band, Legend, NoteBanner, toneOf, CW, CH, dg } from './diagrams';

export const MY_DIAGRAM: React.FC = () => {
  const f = useCurrentFrame();
  const { fps } = useVideoConfig();
  const t0 = seqAt(f, fps, 0, 0.3, 0.1);          // 第 0 个元素，0.1s 后开始出现

  return (
    <div style={{ ...dg, position: 'relative' }}>
      {/* 标题画在 HTML 层，不占 SVG 坐标 */}
      <DTitle text="主标题" sub="副标题，一句话说清这张图在讲什么" op={t0} />

      <svg style={dg} viewBox={`0 0 ${CW} ${CH}`} preserveAspectRatio="xMidYMid meet">
        {/* 步骤卡：op 用 seqAt 错峰，让画面"长"出来 */}
        <NodeBox x={120} y={220} w={226} h={138} op={seqAt(f, fps, 0, 0.3, 0.5)}
                 title="接收请求" lines={['校验签名', '解析参数']} tone="blue" />

        {/* 箭头：dash="0" 实线，dash="10 8" 虚线 */}
        <Arrow x1={354} y1={289} x2={432} y2={289} op={seqAt(f, fps, 0, 0.3, 0.8)} dash="0" head={16} />

        {/* 药丸标签 */}
        <ChipS x={470} y={270} text="校验通过" op={seqAt(f, fps, 0, 0.25, 1.1)} tone="teal" size={24} />

        {/* 分层条 */}
        <Band x={120} y={430} w={620} h={128} op={t0} label="应用层" desc="业务服务 / 编排 / 权限" tone="teal" />

        {/* 底部提示条（amber=注意，blue=说明，danger=风险） */}
        <NoteBanner x={330} y={620} w={940} op={seqAt(f, fps, 0, 0.4, 2.4)}
                    title="关键点：第 3 步是唯一的写操作" sub="其余步骤幂等，失败可安全重放" />

        {/* 图例 */}
        <Legend x={120} y={760} op={seqAt(f, fps, 0, 0.4, 3.0)}
                items={[{ text: '读操作', color: C.primaryLite }, { text: '写操作', color: C.accentLite }]} />
      </svg>
    </div>
  );
};
```

### 颜色语义（`tone`）

| tone | 用途 |
|---|---|
| `blue` | 主流程 / 平台侧 |
| `teal` | 强调 / 被讲的那一步 |
| `amber` | 注意、约束、需要人工介入 |
| `danger` | 风险、失败分支、被拒绝的路径 |
| `plain` | 中性元素、外部系统 |
| `dark` | 弱化背景元素 |

### 三条硬规则

1. **只用 SVG 画图体**。HTML 和 SVG 混排会让坐标无法预测。
2. **每个元素都用 `seqAt` 错峰出现**。按下讲顺序排 `delay`，画面跟着解说走。整张图同时出现是最常见的败笔。
3. **写完自己估一遍文字宽度**：中文 ≈ 字号 × 1.0，英文 ≈ 字号 × 0.55。`ChipS` 的宽度用 `chipW(text, size)` 算，别手算。

### 排一排标签时，**必须用 `ChipRow`，不要手写 for 循环**

一排 chip 最常见的 bug 是**互相压字**（`规则引擎` 和 `状态机` 叠成 `规则引擎状态机`）。根因是用"当前标签的宽度"去推下一个标签的 x：

```tsx
// ✗ 错：标签长度不等时必然追尾
chips.map((m, j) => <ChipS key={m} x={x + j * (chipW(list[0], 24) + 18)} ... />)
```

`ChipRow` 按**每个标签自己的实际宽度**累加，并在超出画布时渲染一条可见的红色警告，不会安静地画到画布外面：

```tsx
import { ChipRow } from './diagrams';

<ChipRow x={478} y={352} items={['Web 控制台', 'REST API', '定时任务']}
         ops={[1, 0.8, 0.6].map((k, i) => seqAt(f, fps, i, 0.25, 0.8))}
         tone="blue" size={24} maxRight={1500} />
```

参数：`x/y` 起点、`items` 文案数组、`ops` 每个标签的不透明度（配 `seqAt` 错峰）、`tone`、`size` 字号、`gap` 间距、`maxRight` 右边界（默认 1600）。

> 换行也不要用手算坐标——超宽就**减少标签数量或缩小字号**，别让它溢出画布。

### 画完必须自检

- 文字有没有溢出 `rect`？（尤其中文标签）
- 有没有元素被画到 x > 1600 或 y > 826？（会被静默裁掉）
- 在 826 高度里，最下面一个元素的下沿 + 40px 之内有没有留白？
- **探针的两帧都看过没有**（入场态 `_a` 看错峰起始、稳定态 `_b` 看最终落位）

## 四、分镜（`script/storyboard.json`）

### 核心约定：**按段内比例切分，不写绝对秒数**

配音重合成后每段时长会变。按比例切，分镜自动跟随，不用回头改。

```json
{
  "brand": "某某平台",
  "endTitle": "某某平台 · 订单模块",
  "endSubtitle": "从下单到履约，全链路可追溯",
  "endFooter": "PRODUCT V1.0",

  "chapters": [
    { "name": "订单受理", "from": "订单受理" },
    { "name": "库存校验", "from": "库存校验" },
    { "name": "结算对账", "from": "结算对账" }
  ],

  "scenes": [
    { "seg": "片头", "f0": 0, "f1": 1, "kind": "cover",
      "shot": "shots/00-cover.png", "title": "订单模块", "subtitle": "从下单到履约", "chapter": "" },

    { "seg": "整体架构", "f0": 0, "f1": 1, "kind": "diagram", "id": "ARCH",
      "chapter": "整体架构", "callout": "请求自上而下穿过四层" },

    { "seg": "订单受理", "f0": 0.0, "f1": 0.55, "kind": "diagram", "id": "ORDER_FLOW",
      "chapter": "订单受理", "callout": "一次下单，四个动作" },

    { "seg": "订单受理", "f0": 0.55, "f1": 1.0, "kind": "shot", "shot": "shots/01-order-list.png",
      "chapter": "订单受理",
      "focus": [{ "x": 0.10, "y": 0.09, "w": 0.63, "h": 0.05, "label": "筛选与搜索" }],
      "callout": "按状态一眼看出卡在哪", "note": "待审核仍需人工确认" },

    { "seg": "收尾", "f0": 0, "f1": 0.7, "kind": "diagram", "id": "CHAIN", "chapter": "" },
    { "seg": "收尾", "f0": 0.7, "f1": 1, "kind": "end", "chapter": "" }
  ]
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `seg` | 引用 `narration.json` 里的段名 |
| `f0` / `f1` | 在本段时长里的起止比例（0~1） |
| `kind` | `cover`（片头）/ `diagram`（图表）/ `shot`（截图）/ `end`（落版） |
| `id` | `diagram` 用，对应 `diagrams.tsx` 里 `DIAGRAMS` 的键 |
| `shot` | `shot` 用，相对 `remotion/public/` 的路径 |
| `chapter` | 章节角标文字；片头/落版留空 `""` |
| `callout` | 左下角说明条（≤ 14 字，会折行，用 `text-wrap:balance`） |
| `note` | 右下角边界提示（橙色，≤ 14 字），**用来写"这里的边界/限制"** |
| `focus` | 高亮框数组，坐标是相对整图 0~1 比例 |

### callout / note 的用法

这两个是视频里最容易被忽略、但最能提高可信度的元素：

- **callout（左下，青色）**：这一小段画面在讲什么。写成"结论"而不是"标签"
  - 差：`订单列表`　好：`按状态一眼看出卡在哪`
- **note（右下，橙色）**：这里的边界、前提、注意事项。**每章至少写一条**
  - `待审核仍需人工确认` / `只读派生，不改源文件` / `过期需要重新生成`

### 分镜自检

`make_props.py` 跑完会打印自检提示，重点看三类：

1. 分镜之间有缝隙或重叠（段名写错、比例没接上）
2. `id` 为空 / 截图文件不存在 / `focus` 缺字段或超出画布
3. 时间倒挂（`end <= start`）

## 五、章节角标

`chapters` 里每一项就是一个角标（左上角 `名称 01/03`）。规则：

- 章节顺序 = 数组顺序
- `to` 省略时，结束时间自动取下一章的 `from`；最后一章取全片结束
- 片头和落版**不要**列入 `chapters`，否则角标会出现在片头上（组件本身也会按 `chapter` 为空来隐藏，但列进去会打乱编号）
