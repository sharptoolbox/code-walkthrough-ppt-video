# 02 · 界面重绘：从源码还原可截图的仿真页面

这套流水线**不要求系统能跑起来**。老系统依赖内网、许可证过期、前端构建链断掉都很常见；但界面是最有说服力的讲解载体。做法是：**从前端源码里读出页面的结构与文案，用纯 HTML 重新画一个静态页面，再截图**。

> ### 合规前提（必须遵守）
> 1. 重绘页面里**不得出现真实客户数据、真实账号、密钥、内网地址**。一律用仿真数据。
> 2. 视频里如有台词提到界面，用「界面示意」而非「系统实际截图」的措辞。收尾的边界声明里也要说明。
> 3. 原系统的 Logo、商标，除非用户明确授权，否则用中性文字标题替代。

---

## 一、从源码里读什么（"还原清单"）

按顺序扫，每一步都往同一张清单里填。**只读与"长什么样"有关的部分，不要读业务逻辑。**

| 要还原的东西 | 在哪读 | 读法 |
|---|---|---|
| 页面标题 / 导航结构 | 路由表、菜单配置 | 路由的 `meta.title`、菜单 `name`；层级就是导航层级 |
| 区块划分 | 页面组件模板 | 找出「查询条件区 / 操作工具栏 / 表格 / 分页 / 抽屉 / 弹窗」这几块 |
| 表格列 | `columns` 定义、`<el-table-column>`、表头文字 | 列的 `label` 即表头文案，顺序即列顺序；`width` 决定宽度比例 |
| 表单项 | 表单 schema、校验规则 | `label` 是字段名；`required` 加红星；`type` 决定控件（输入框/下拉/日期/开关） |
| 状态标签 | 枚举 / 字典常量 | 枚举值的中文名 + 颜色语义（成功/警告/危险/中性） |
| 主色与字体 | CSS 变量、less/scss 变量、`ConfigProvider theme` | 拿到主色，其余自己配 |
| 按钮与操作 | 表格行操作列、工具栏按钮 | 按钮文案通常就是"下一步会讲的功能" |
| 示例数据 | mock 文件、`__mocks__`、注释里的示例 | **只借用字段结构与取值风格**，值自己编 |

### 一个常见误区

不要试图"把源码跑起来看真实页面"。前端源码经过打包、主题注入、权限过滤之后，直接读反而更准；而且真实环境经常起不来。**读源码 = 更可控的还原。**

## 二、还原到什么程度

**结构 1:1、文案 1:1、数据仿真。** 判断标准很简单：

> 一个用过这个系统的人，看一眼就认得出"这是那个页面"；但仔细看数据，发现不是真实数据。

具体尺度：

| 要像 | 可以不像 |
|---|---|
| 导航层级与菜单文案 | 菜单里的图标（用统一符号即可） |
| 页面标题、表头、按钮文案 | 精确的像素间距 |
| 区块的位置关系与相对大小 | 真实的主题皮肤细节（圆角、阴影） |
| 状态标签的文字与色彩语义 | 复杂的交互动效 |
| 字段顺序 | 数据的真实取值 |

## 三、构图规范（不遵守就会在视频里出问题）

| 项 | 值 | 原因 |
|---|---|---|
| 画布 | **1600 × 900**（16:9） | 视频画面卡是 1400×788，比例一致才不会被裁、焦点框才不会错位 |
| 缩放 | 100%，无滚动条 | `prep_shots.py` 会按 16:9 再裁一次，有滚动条会白边 |
| **安全边距** | **左 / 右 ≥ 28px，上 / 下 ≥ 20px 不放关键内容** | 见下方「缓推镜头会裁边」 |
| 主字号 | 表格正文 16~17px，表头 16px，页面标题 20~22px，导航 17~18px | 1600 宽下这个字号在视频里清晰可读 |
| 侧边导航宽度 | 200 ~ 240px | 太窄画不下中文菜单，太宽挤压内容区 |
| 顶栏高度 | 52 ~ 60px | |
| 配色 | **跟视频同色系（深色）** | 视频是深色背景，中间突然插一张白底页面会很刺眼 |
| 表格行高 | 40 ~ 48px | 一屏能放 8~12 行，信息密度刚好 |

### 缓推镜头会裁边 —— 这是最容易忽略的一条

截图分镜带一个缓慢推进的镜头（`scenes.tsx` 里的 Ken Burns：`scale 1.02 → 1.004`，伴随 `±5px / ±4px` 平移）。它的代价是**对截图做一次等比裁边**：起始帧大约裁掉左右各 **20px**（图像空间）。

换算关系（记住这个比例，调参时用得上）：

```
卡片宽 1400 → 图片宽 1600，所以「卡片像素 × 1.143 = 图像像素」
幅度 A 的裁边量 ≈ (1400 × A / 2 + 平移量) × 1.143
```

所以：

- **关键文字不要贴边**。骨架里侧边导航的左边距已设成 22px、顶栏 30px，就是为这个留的余量。自己新写页面时照此办理。
- 想加大镜头幅度（比如 `scale 1.06`）时，**先确认截图左右各有 ≥ 54px 空白**，否则品牌名/菜单会被切掉一半——这种"切了半个词"的画面很显眼。
- 反过来，如果截图左右本来就窄，**把幅度调小**（`scenes.tsx` 里 `kb` 与 `px`/`py` 是同一条注释下的三个数），不要硬裁。

> 桌面骨架的这套边距已经过实测（探针帧确认无裁切）；换用自己画的页面时，把这条当检查项过一遍。

### 浅色系统怎么办

原系统是浅色时，**重绘成深色版的同一页面**（结构文案不变，配色换成上面这套深色），画面统一性更好。代价是"看起来不像原系统"——所以：

- 解说里不要声称"这是系统界面截图"
- 收尾边界声明注明"界面为按源码结构重绘的示意页面"

## 四、动手：三套骨架

`assets/ui-shell/` 里给了三套可直接改的骨架：

| 文件 | 用途 |
|---|---|
| `shell-desktop-dark.html` | 中后台管理系统（左侧导航 + 顶栏 + 表格），深色。**最常用** |
| `shell-desktop-light.html` | 同上，浅色版逻辑结构 |
| `shell-mobile.html` | 移动端 / 小程序（顶部标题栏 + 卡片列表） |

用法：复制一份到工程目录的 `ui/` 下改名，然后按"还原清单"改文案、改列、改状态标签。

**一张截图 = 一个 html 文件**，文件名就是截图名（`order-list.html` → `order-list.png`）。

### 修改时的手工核对

改完 HTML 之后，**先在浏览器里打开看一眼**（尺寸设 1600×900 的窗口，或直接用无头截图看结果）。重点检查：

- 文字有没有溢出容器（中文比英文宽，容易挤爆）
- 表格列加起来会不会超宽（给固定宽度列分配时留 5% 余量）
- 状态标签的颜色语义对不对（成功=绿、警告=橙、危险=红、中性=灰）

### 版式稳定的关键：**表格区用绝对定位切三段**

中后台页面最容易翻车的地方是"表格区高度不确定"，导致**分页器被挤出画面**或底部挂一条空白带。用 flex 或 `margin-top:auto` 试着挤，在不同内容量下表现不稳定。

**可靠做法**：把表格容器切成三个**绝对定位**的区块，高度完全确定，谁都挤不动谁。

```css
.tablewrap{flex:1;min-height:0;position:relative;background:var(--card);
  border:1px solid var(--line);border-radius:10px;overflow:hidden}
.tbar  {position:absolute;left:0;right:0;top:0;    height:52px; ...}   /* 工具栏 */
.tbody {position:absolute;left:0;right:0;top:52px; bottom:54px;overflow:hidden} /* 表体，弹性 */
.pager {position:absolute;left:0;right:0;bottom:0; height:54px; ...}   /* 分页器 */
```

三套骨架里都是这么写的，**照抄这套结构**，后面改内容不会把版式改崩。

## 五、截图

```bash
python <skill>/scripts/shoot_page.py --in ui --out shots_raw
```

脚本做的事：找 Chrome/Edge → 无头打开每个 html → 截成 1600×900 PNG。

**两个必知的坑**（脚本里都已处理，自己写截图命令时要注意）：

1. **Windows 显示缩放**会让 `--window-size` 失效（150% 缩放下 1600×900 只截出 1080×617）。必须加 `--force-device-scale-factor=1`。
2. **`--window-size` 是窗口尺寸，不是视口尺寸**。窗口标题栏和边框会吃掉约 **16×95px**，真实视口只有 1584×805——页面最底下那条（分页器、底部按钮）永远拍不到，而图片尺寸看起来完全正常。脚本的做法是**窗口开大一圈再裁**：`--window-size=w+40,h+120`，截图后 `crop(0, 0, w, h)`。

> 如果输出尺寸不是 1600×900，或者尺寸对但**底部内容缺了一块**，先查这两项，**不要先去改 CSS 布局**。

### 归一化

```bash
python <skill>/scripts/prep_shots.py --raw shots_raw --out remotion/public/shots
```

这一步把任何来源的截图（含外部提供的真实截图）统一到 1600×900，并生成 `contact_sheet.png` 拼版。**每次出完截图先看拼版**，一屏看完所有画面，比逐张点开快得多。

## 六、下一步：标定焦点框

截图有了之后，要在 `storyboard.json` 里给每个 shot 分镜标 `focus`（讲解时高亮的那块区域）。坐标是**相对整图的 0~1 比例**：

```json
"focus": [{"x": 0.10, "y": 0.09, "w": 0.63, "h": 0.05, "label": "筛选与搜索"}]
```

`x`=左边距/图宽，`y`=上边距/图高，`w`/`h`=框宽高/图宽高。

标定方法（很快，2 步）：

1. 打开 `contact_sheet.png` 或原图，按比例估一个值（不用很准，量级对就行）
2. 跑 `probe_render.sh`，看抽出来的帧，高了/低了/宽了就微调

**不要凭记忆写坐标**——`objectFit:cover` 的裁切会让偏差放大。探针帧是唯一可靠的验收手段。

一个分镜可以有多个 focus 框；只有一个框时组件会自动压暗框外区域（聚光灯效果），有多个时只画框。
